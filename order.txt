或先准备本地模型并指定 --policy.pretrained_path=/absolute/path/to/pi05_base。
可用 --dataset.video_backend=pyav 避免依赖 TorchCodec 解码库（下方训练命令已指定）。
同步/异步 eval 入口已适配共享库；请在各评估环境安装根目录共享库及模型依赖，

请根据需要选择数据集，本文保留现有命令的数据选择。

    --dataset.video_backend=pyav \
    --dataset.compress_dex3_actions=true \
    --policy.path=lerobot/dm05_base \
    --policy.use_relative_actions=false \
    --policy.chunk_size=50 \
    --policy.n_action_steps=4 \
    --policy.vlm_gradient_checkpointing=true \
    --policy.ae_gradient_checkpointing=true \
    --policy.freeze_vlm_embedding=false \
    --policy.compile_model=false \
    --policy.dtype=bfloat16 \
    --policy.device=cuda \
    --policy.push_to_hub=false \
    --output_dir=/home/jchen572/code_file/RBM_lerobot/lerobot/outputs/dm05_g1_dex3_16d \

    --batch_size=1 \
    --steps=40000 \

G1 Dex3 压缩模式不要启用 use_relative_actions：DM0.5 相对动作要求 state/action 维度相同。

取消旧夹爪0.12秒平滑和换向加速度限制；在0.5裁剪保留之后增加0.08秒时间常数的输出低通平滑，从上一条SDK指令推进，不重新缩放最终目标；r/b不启用。恒定目标约0.24秒完成95%的指令过渡，不保证机械到位时间。设 --safe-gripper-output-smoothing-s 0 关闭。身体控制及其保护参数不变。
仍同线程合并下发50Hz，不启用独立夹爪线程。40单位/s、每周期0.8单位仅用于原始裁剪基准；保留系数0.5时不再是最终指令的硬速度上限。设 --safe-gripper-limit-retention 1 恢复原行为。
必须同步服务端并使用下方 --safe-gripper-feedback-tracking 重启；旧服务不支持此参数。
客户端先对新动作块前5步的夹爪目标做Add式过渡，参考上一条实际下发目标；首块不处理，仅夹爪生效。10Hz下约0.5秒，30Hz下约0.167秒。设 astribot_gripper_chunk_blend_steps=0 关闭。
过渡后再做松开确认；持续松开目标仍会执行，不能替代抓持检测。
客户端增加夹爪松开确认：左右独立，下降超过0.5单位且持续0.3秒才放行；确认后连续释放不重复等待。关闭方向直接放行，r/b后重置。
该过滤不检测接触，不能保证抓持；正常释放也会延迟约0.3秒，块间持续错误松开仍会放行。设 astribot_gripper_release_confirm_s=0 可关闭。
不会把中间目标自动变成全闭合目标。关节速度与角速度是同一指标；
这里没有末端笛卡尔线速度保护。指令经过限速/限加速度生成，反馈超限则停发并报错退出。
保留反馈超时与范围检查，范围按本节1.0 rad配置；退出不自动回位/开爪，故障需检查后重启。
实测加速度使用至少100ms的非重叠窗口（首次需两个窗口），短促尖峰敏感度低于逐周期差分；逐周期转速保护保留。
等待 r/s 时每0.25s刷新原目标并检查故障，不追随反馈漂移。
SDK反馈差分可能因噪声/刷新率触发保护；不要直接放宽阈值。软件停发不等于硬件急停。
实体急停必须可用；没有实机安全验证，不能保证取消SDK已接收的运动。

与只读命令相比增加 --execute；按键无需回车（在工作站交互终端运行）。
r：限速对齐 --episode 所选示范首帧 observation.state（包含夹爪），到位后等待s；运行中r会暂停策略并重新对齐。
s：开始策略；也可以不按r，直接从现场摆好的姿态开始。
初始姿态记录为第一次使能前的真实反馈，r对齐后不会覆盖它；不是关节全零，也不是示范首帧。
实时模式不写--steps表示持续运行，直到q/Ctrl+C或故障停止；显式--steps=N仍限制控制周期数（含等待）。离线dataset模式默认仍为100帧。
q / 第一次Ctrl+C / 达到显式指定的steps：停止取新策略动作，双臂缓慢返回初始关节姿态，夹爪保持退出时开口。
初始姿态若有小幅越过控制器限位的偏差，回位目标裁到名义边界，不保证精确回到越界读数。
回位中再次q或Ctrl+C：中止回位并请求SDK急停；断连、硬件/反馈/相机故障或回位超时也直接停止，不强行回位。
正常回位后保持最终位置，不发送急停、不失能、不自动张爪；保持21.0服务运行，下一轮直接重新运行评估命令并按r/s。
保持期间仍监测反馈、控制器状态、相机和跟踪偏差；故障或关闭发送端服务仍会急停，必要时需手动reset。保持不是零力矩，请勿强行手掰。
return-joint-speed为r对齐/退出回位的关节目标变化率（rad/s），默认0.15；return-gripper-speed为r对齐夹爪目标变化率，默认0.01。
r对齐/q回位采用至少30Hz目标更新及平滑起停插值；即使frequency=10，这两段也以30Hz更新，策略执行频率仍为10Hz。
两者同时受客户端joint/gripper-speed和服务端上限限制；return-timeout是一次对齐/回位的最长时间（秒）。
慢速回位不保证路径无碰撞；模型计算期间q/Ctrl+C请求在本次推理返回后处理，不替代实体急停。
关节/夹爪速度上限取服务端和客户端较小值，调速时两端一起改；跟踪偏差阈值在21.0修改。
动作超时取服务端timeout和客户端command-timeout较小值；等待s时持续保持目标和刷新动作心跳。
日志phase区分policy/alignment/return，保存state/command/目标及耗时，旁边.run.json保存推理配置。
发送端与评估端都需要同步本次更新；旧发送端缺少finish_hold正常结束接口，会在使能前被拒绝。
